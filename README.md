# Проверка прайс-листа поставщика на 1С

Демонстрационный код для портфолио Алексея Замчевского, подготовленный отдельно от кода работодателей. В комплекте исходники алгоритма и собранная внешняя обработка с формой самопроверки: чтение Excel, проверка и массовое сопоставление строк. Записи справочников и документов нет.

## Состав

Код для просмотра на GitHub:

- [Основной модуль обработки](src/ИмпортПрайса/Ext/ObjectModule.bsl): чтение прайса, проверка данных, сопоставление и 16 проверочных условий.
- [Модуль формы самопроверки](test-harness/FormModule.bsl): серверный обработчик открытия формы, запуск проверок и вывод результата.
- [Готовая обработка для запуска в 1С](ИмпортПрайса.epf): включает основной модуль и настроенную форму самопроверки.

Форма входит в EPF. Файл `FormModule.bsl` содержит ее код, но не описание элементов и привязок событий в XML. При ручном воспроизведении создайте основную управляемую форму с реквизитом `Объект`, перенесите модуль формы и назначьте процедуру `ПриСозданииНаСервере` одноименному событию формы.

- `src/ИмпортПрайса.xml`: дескриптор внешней обработки Designer XML.
- `src/ИмпортПрайса/Ext/ObjectModule.bsl`: алгоритм и 16 проверочных условий.
- `examples/price.csv`: содержимое примерного прайса; для загрузки сохранить в XLSX по правилам ниже.
- `verification.md`: выполненные проверки и ограничения.
- `ИмпортПрайса.epf`: обработка, сохраненная конфигуратором 8.5.1.1522, с формой запуска самопроверки.
- `test-harness/FormModule.bsl`: исходник модуля тестовой формы из EPF. Событие `ПриСозданииНаСервере` назначено в редакторе формы. Исходный XML в `src` содержит только объект и его модуль, без этой формы.

## Контракт файла

Один лист, первая строка строго `Артикул`, `Наименование`, `Цена`, колонки A:C. Артикулы хранить как текст, чтобы сохранялись ведущие нули. Цена: положительное число без разделителей тысяч, символов валюты, процентов или формул; максимум 12 цифр целой части и 2 дробной, разделитель точка или запятая. Рекомендуется текстовый формат ячейки цены. Полностью пустые строки пропускаются. Книга должна быть компактной, без оформления миллионов пустых строк.

CSV не подается методу чтения Excel напрямую. Он служит доступным примером данных для создания XLSX. Файлы XLSX читаются платформой через `ТабличныйДокумент.Прочитать`, без COM и установленного Excel на сервере.

## Как работает

1. `ПрочитатьПрайс` читает файл на стороне сервера/толстого клиента и возвращает таблицу строк.
2. Адаптер конкретной конфигурации заранее получает ВСЕ соответствия по одному выбранному поставщику и артикулам файла одним запросом. Адаптер не включен: без исходников УТ нельзя корректно назвать регистр соответствий и его реквизиты.
3. `ПроверитьПрайс` строит индекс в памяти и обрабатывает строки без запросов внутри цикла. Артикулы сравниваются точно после удаления пробелов по краям; регистр букв не нормализуется.
4. Дубли артикула в файле отклоняются все, даже при одинаковой цене. Повтор одного и того же соответствия не создает неоднозначность, но два разных кода для одного артикула дают ошибку.
5. Результат содержит исходный номер строки, цену, найденный код, статус и сообщение. Статусы: `Найдена`, `Новая`, `Ошибка`. `Новая` требует проверки человеком, а не автоматического создания карточки.

Сложность индексирования и сопоставления обычно близка к O(n+m); коллекции кандидатов для одного артикула предполагаются небольшими. Время проверки измеряется разностью `ТекущаяДата()`, с точностью до секунды. Оно не включает чтение Excel и получение соответствий и зависит от системных часов.

## Подключение к тестовой 1С

Откройте `ИмпортПрайса.epf` через меню «Файл → Открыть» в режиме 1С:Предприятие. При открытии формы запускаются 16 проверочных условий. Успех подтверждается сообщением «Самопроверка пройдена: 16 из 16 условий». 13 октября 2026 года проверка синтаксиса и все 16 условий успешно выполнены в платформе 8.5.1.1522. Чтение реального XLSX отдельно не проверялось; подробности в `verification.md`.

Из серверного кода тестовой базы вызовите:

```bsl
Обработка = ВнешниеОбработки.Создать(ПутьКТестовойОбработке);
ЧислоПроверок = Обработка.ВыполнитьСамопроверку(); // Ожидается 16.

Строки = Обработка.ПрочитатьПрайс(ПутьКФайлуНаСервере);
Связи = Обработка.НоваяТаблицаСопоставлений();
Связь = Связи.Добавить();
Связь.Артикул = "001";
Связь.КодНоменклатуры = "N1";
Результат = Обработка.ПроверитьПрайс(Строки, Связи);
```

Пути должны быть доступны серверу. Этот пример не реализует диалог выбора и загрузку клиентского файла; в управляемом приложении файл сначала передается на сервер штатным механизмом. Все таблицы обрабатываются на сервере. Для реального адаптера вместо строкового кода нужно возвращать ссылку на номенклатуру и учитывать действующие правила поставщиков, характеристики и единицы.

## Что объяснить на собеседовании

Почему поиск вынесен из цикла; как сохраняются ведущие нули; почему неоднозначное сопоставление отклоняется; почему ошибка строки не останавливает остальные строки, а ошибка чтения книги останавливает весь импорт; почему демонстрация не записывает данные; где находится граница с конкретной конфигурацией.

Это пример предварительной проверки и сопоставления, а не готовый промышленный загрузчик цен. Есть только форма самопроверки. Нет интерфейса загрузки файла, записи документов цен, защиты конкурентного создания карточек и конфигурационного адаптера.
